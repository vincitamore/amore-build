# Prokopē — instrument for long goal loops

Named for Greek **προκοπή** (*prokopē*): progress as continuous advancement — the *viator* climb, not arrival. Matches the house lattice floor (never-arriving perfection): the loop is for the road.

> Written for **Arcus Build**: native task-tool dispatch, automatic context compaction (there is no reliable pre-compact hook, so the operational write is agent-owned), the git-committed task file as the durable handoff surface, and the tasks/knowledge/inbox lifecycle from AGENTS.md. The worked numbers below are illustrative — do not hardcode wave rates or domain-specific success bars as universal constants.

## §0 · Self-updating

Keep this skill true when the underlying fact moves:

- **New collapse mode exhibited on a long goal** → add to §3 Collapse catalog with exhibit path; if it generalizes, add a refuse rule.
- **New companion skill contract** (sortes/forge-master/isda + house lifecycle surfaces) → update §5 Composition.
- **Session re-arm or compactification protocol changes** → §4, §7, and any local templates/references.
- **Pressure-health metrics renamed** → §4 and local pressure-health notes.
- **Tip / orientation-packet shape changes** → §6–§7 and goal-brief template.
- **Your own practice moves past what is written here** → this file is yours;
  rewrite it rather than working around it.

Ephemeral campaign state lives in the goal’s own surfaces (attack graph, status) — **not** here.

## §1 · Identity

**You author and maintain goal loops** — the architecture of pursuit under bearer discontinuity (sessions, models, context windows, **compactification**).

| This skill **is** | This skill **is not** |
|-------------------|------------------------|
| How to write a goal brief that survives 24h **and** mid-session compact | A substitute for domain skill (math, code, net) |
| How to structure working surfaces (graph, ledger, notes) so tips outlive context | forge-master (no agent dispatch) |
| How to keep **honesty** and **pressure** both alive across boundaries | A checklist that completes the goal |
| How to wire sortes / isda / forge-master into the loop | Universal wave-count or hour-count quotas as success |
| Compactification survival methodology (pre/post boundary protocols) | A compaction-hook substitute (automatic summary is not tip-write discipline) |

**One-line law:** True success is named and hard; process volume is never success; state lives in **tips on disk**, not in the context window; when pressure dies **or** a compact boundary corrupts continuity, **re-arm** — do not add more waves in the same dead or ghost basin.

## §1.1 · Goal classes (scope the doctrine)

Not every multi-session goal is open-ended research. **Name the class in the brief.**

| Class | Shape | Sortes floor | Compactification package | Honest-negative product |
|-------|-------|--------------|--------------------------|-------------------------|
| **A** Open constructive (research until True success) | Attack graph + pressure full | Mandatory multi-arm after kickoff | **Required** (full §7) | Forbidden as completion |
| **B** Assay / survey | Bounded questions; time/scope exit allowed | Soft-ref multi-arm | Required light (orientation packet + tip write) | Allowed if questions answered |
| **C** Ship / instrument | Deliverable + tests | Review catalog if code multi-arm | Tip = branch/PR + test bar; light orient packet | N/A |
| **D** Ordinary multi-session | Light surfaces | Optional | Optional tips; still refuse summary-as-warrant | Optional |

Class A is the full package. Do not apply class-A refuse lists to class B/C by default.

## §2 · Dual success modes (non-negotiable)

Every goal brief must separate:

| Mode | Meaning | Completes the task? |
|------|---------|---------------------|
| **True success** | Domain predicate named by the operator (theorem, system, proof, deploy) | **Yes** — only this (or operator stop) |
| **Continuable handoff** | Surfaces updated, tip ordered, pressure noted, task still active | **No** — survival across sessions **and** compact boundaries |

**Anti-patterns (refuse as “done”):**

- Minimum N waves / pipelines / forge manifests
- “Honest negative” as campaign product when the brief forbids early close
- “Substantial progress” checklist without True success
- Soft-KEEP chains elevated by vocabulary change alone
- **Summary / compact residue treated as completion evidence**

Honesty can hold while altitude collapses. Continuity assumed in chat while tips lag is not compact survival.

## §3 · Collapse catalog (from corpus; transfer carefully)

Use these as **diagnostic lenses** when a long goal fails. Exhibits are formative; the *mode* generalizes.

| Mode | Symptom | Prescription |
|------|---------|--------------|
| **Count-collapse** | Wave/commit count treated as progress | Bar is True success only; handoff ≠ done |
| **Volume ≠ altitude** | Huge graph, lateral re-skins | ISDA ΔND on wave deltas; change-the-engine |
| **Kill-pressure death** | KILL rate → 0; late waves never falsify | Pressure health (§4); re-arm session |
| **False decorrelation** | Sortes names vary; outcome skeleton freezes | Outcome-shape check; force falsifying arm |
| **Geometric costume** | One model re-skinned across vocabularies | Name generative engine class; zero-entry class next |
| **Adversarius sleep** | No external attack after early hours | Mandatory adversarius cadence in brief |
| **Trail lapse** | No tags / no `not surfaced:` | Hygiene fail; re-arm; draw unused |
| **Elevation by packaging** | Substrate renamed as summit claim | Standing blocks + warrant-scale |
| **Tip lag** | Status tip behind graph tip | Resume from **last tip**, not mid-file “status head” |
| **Surface bloat** | Tracking surfaces grow until orienting on them costs more than they carry | **Era rotation**: freeze old surfaces as read-only forensics; scaffold fresh era artifacts |
| **Overfit gospel** | Prior campaign numbers as universal law | Prefer modes over constants |
| **Summary-as-warrant** | Compact/summary text treated as exhibit for bars or claims | Re-read tips; summary is forensics only (§7) |
| **Ghost continuity** | Assumes standing blocks / draws / next moves still held in chat after boundary | Orientation packet; re-draw sortes |
| **Tip-erasure** | Compact or pause accepted without tip write | Pre-boundary protocol mandatory |
| **Re-constitution from summary** | Doctrine / bar rewritten from blurred memory | Brief is law; do not re-author under compact fog |
| **Soft-elevation after compact** | Summary “progress” read as altitude | Dual success modes; tips only elevate |
| **Bar-under-encodes-rulings** | True-success bar verifies the mechanical deliverable but omits a quality dimension the operator's rulings implied | Author the bar FROM every operator ruling; before declaring success, diff the bar against the Decision log |
| **Recurrent bar-falsification → verdict-authority inversion** | Agent re-authors the bar after operator falsification and self-declares again | After the SECOND falsification, revoke self-declaration: completion = an EVIDENCE PACK presented to the operator |
| **Deferral-as-completion** | A gap-note shipped as if it resolved a "make it fully X" ruling | A gap-note never completes a "fully X" ruling without explicit operator acceptance |
| **Operator-as-gap-discovery-mechanism** | Operator falsifies BY USING THE PRODUCT repeatedly | Multi-surface adversarial audit fanout; census every BLOCKER by name |
| **Vacuous-completion** | Universally quantified clause over a set the agent discovers — satisfied by finding nothing | Pair with a **pre-named inventory**; exhaust open-ended search never discharges itemised gates |

**Adversarius refuse-list for *this skill*:** do not ship a skill that is one prior campaign with nouns sanded off; do not make hour/wave counts a hard universal; do not clone forge-master; do not treat automatic summary machinery as a substitute for tip-write discipline.

## §4 · Pressure health (required package)

Honesty can hold while **search dies**. Instrument both. Compact boundaries often **mask** pressure death (summary still sounds productive).

### Minimal signals (per session or per ~N waves)

| Signal | Healthy | Sick |
|--------|---------|------|
| **Live falsifications** | ≥1 real kill/demotion of a *load-bearing* claim recently | Zero live kills across a long tail |
| **Sortes hygiene** | Draws tagged; `not surfaced:` present on multi-arm waves | Untagged multi-arm / trail silence |
| **Outcome diversity** | Draw changes *shape* of work, not only titles | Fixed template regardless of draw |
| **Adversarius touch** | Recent external attack on elevation path | Only self-review |
| **Engine class ledger** | New attempts cite engine class; avoid pure re-skin | Same generative engine, new nouns |
| **Tip freshness** | Graph tip + status tip agree; written before last boundary | Tip lag or tip-erasure after compact |

### Re-arm rule (default operational fix)

When pressure is sick **or** context depth is high (long marathon) **or** post-compact orientation fails (§7):

1. **Checkpoint** — attack graph tip + status continuable tip + pressure line + commit.
2. **End the session** (do not keep pumping waves in the same basin or ghost-continuous basin).
3. **Re-post the goal brief** into a **fresh** session (same task file).
4. Fresh context restores kill pressure, tag discipline, and genuine lens-following **if** the graph carries state.

Cadence is **heuristic**. Prefer **pressure-signal and tip-integrity triggers** over fixed clocks. Operator may set domain-specific thresholds in the brief.

**Anti-thrash:** re-arm is not free. If two consecutive sessions re-arm without a load-bearing kill *or* an engine-class change, stop pumping — write a plateau note and change the generative engine before the next re-post. Count of re-arms is not progress.

**Operator governance (class A):** brief should say who may pause, who re-posts after unattended runs, and what the operator decides vs the agent (decision tickets, not only “stop”).

### Sortes doctrine (goal-loop floor)

When [[skill://sortes]] is present, draw from the appropriate catalog for the arm count:

- Tag every multi-arm wave with drawn lens names.
- End consumer artifacts with `not surfaced: …`
- If tags lapse for a long stretch → **hygiene fail** → re-arm session, do not “push through.”
- **Outcome-shape check:** if the wave skeleton is identical across different draws, decorrelation failed — force a falsifying arm or change engine class.

### ISDA (prokope application — not native isda clauses)

Full ISDA lives in [[skill://isda]] when present. **Prokopē applies** those primitives as light checkpoints:

| # | Gate (prokope) |

Do not treat “forge ran” as altitude or True success. Soft-ref sortes when multi-arm homogeneous. Child agents never had the transcript — dual-write is their compactification organ; goal tips remain the campaign organ.

## §6 · Working surfaces (goal-loop state architecture)

Generalize the pattern; rename for domain. **Surfaces exist so compactification and session death are survivable** — not as documentation theater.

| Surface | Role | Package risk |
|---------|------|--------------|
| **Task / goal brief** | Law: True success, process constitution, refuse list, orientation packet | Stale doctrine if not updated |
| **Attack graph** (or equivalent search log) | Append-only search SoR; **tip** = continuable frontier | Node-count cosplay |
| **Status ledger** | Elevation registry + standing blocks + **OPEN tip** | Tip lag behind graph |
| **Research notes / intermediate claims** | Soft consolidation; non-claim banners | Soft ≅ win |
| **Executable exhibits** (code, proofs, tests, assays) | Typed truth; refuseElevation gates | Volume cosplay |
| **Git tip / branch** | Landable continuity | main ≠ success |

**Promotion flow:** exhibit → graph node → (optional) research note → status ledger only if elevation bar met → never reverse (ledger cannot invent altitude).

**Resume rule:** always from **last Continuable tip** + attack-graph tip, never from a mid-file “status head” that may lag, never from compact summary.

**Tip contract (every surface):** one named tip; tip write atomic before boundary; resume reads tip only; tip lag = hygiene fail before new waves.

## §7 · Compactification survival methodology

> **This is a first-class operation-space.** Re-arm, dual success modes, and surfaces are necessary but incomplete if the *boundary itself* is never named. Long goals fail here when doctrine lives in chat and dies at compaction / session cut.

### Two boundaries

| Boundary | What happens | Continuity organ |
|----------|--------------|------------------|
| **Soft compact** | Mid-session summarization; same session continues with degraded memory | Disk tips + brief (must already be written) |
| **Hard re-arm** | Session ends; fresh session re-posts goal brief | Same surfaces + cold brief re-read |

This harness runs compaction **automatically** when context fills. Do not depend on a pre-compact hook to write tips — Prokopē owns the operational write. What the harness gives you: automatic compaction plus the git-committed task file as the durable surface the next session orients from; the handoff discipline is the substance, not the machinery.

### One law

**Anything load-bearing after a boundary must already be on disk in tip-form before the boundary — or it is already lost.**

Context is scratch. Surfaces are the continuity organ. **The summary is not a surface.**

### What must never live only in chat

True success bar · standing blocks / refuse list · graph tip + status OPEN tip · ordered next moves · recent load-bearing kills · engine class of current attempt · in-flight sortes tags / `not surfaced:` · operator decisions that change the bar.

### Orientation packet (cold re-entry order)

Every class A (and light class B) brief names an **ordered re-read set**:

```text
1. Task / goal brief (law + True success + refuse list)
2. Status ledger tip (elevation + OPEN + standing blocks)
3. Attack-graph tip (search frontier + ordered next)
4. Exhibit pointers cited by tip only
5. Last pressure note (if separate)
```

**Tips first.** Do not open with “read the whole graph.” Expand on demand.

### Pre-boundary protocol (before soft compact or hard pause)

1. Graph tip: last nodes + **ordered next moves** (constructive).
2. Status tip: True success still OPEN (unless truly elevated); standing blocks intact.
3. Pressure line: last live kill **or** explicit “pressure sick → re-arm”.
4. Git land if durable work exists.
5. Only then accept compact / end session.

**Refuse:** “I’ll remember / the summary will keep it” without tip write.

### Post-boundary protocol (after compact or cold start)

1. Run orientation packet **from disk**.
2. **Refuse summary-as-warrant** for: True success status, standing blocks, tip identity, kill ledger, operator bar changes.
3. If tip lag, pressure sick, or standing-block amnesia → **hard re-arm**, do not soft-continue into more waves.
4. Re-draw sortes for the next multi-arm wave.
5. Resume from **ordered next moves** on the tip — not from summary “progress so far.”

### Soft continue vs hard re-arm

| Signal | Prefer |
|--------|--------|
| Tips written, pressure healthy, one compact, brief still loadable | Soft continue **after** post-boundary re-read |
| Tips stale/lag; pressure sick; standing blocks uncertain; multiple compacts; marathon depth | **Hard re-arm** |
| Summary claims altitude the tips do not | Hard re-arm + plateau note |
| Two soft-continues after compact without load-bearing kill or engine change | Hard re-arm + engine change before re-post |

### Brief design tests (compactification package)

A class A brief fails this surface if it lacks: ordered orientation packet paths · pre-boundary tip-write rule · post-boundary “re-read tips; refuse summary warrant” · True success/refuse list in the task file (not chat lore) · resume language pointing at tips (not “conversation so far”) · boundary-triggered re-arm criteria.

## §8 · Authoring a goal brief (procedure)

1. **Name True success** in one falsifiable sentence (domain predicate).
2. **Name failure modes of prior attempts** (explicit “do not repeat”).
3. **Obstacle protocol** — name → fan-out ≥3 → ≥1 foundation rewrite → ≥1 absurd-falsifiable → experiment → loop (adapt counts to domain; keep the *shape*).
4. **Honesty package** — standing blocks; “what is not success”; warrant-scale language.
5. **Pressure package** — kill/falsify cadence; adversarius cadence; sortes mandatory rules; re-arm triggers.
6. **Surface contracts** — which files are SoR for search vs elevation; **named tips**.
7. **Compactification package** — orientation packet (ordered paths); pre-boundary tip write; post-boundary refuse summary-as-warrant; soft-continue vs hard re-arm criteria.
8. **Companion skill block** — paste sortes/forge-master/isda commands into goal prompt when those skills are installed.
9. **ISDA C0–C1** — telos + substrate explicit; C5 smoke on the brief itself (280–800 chars still preserve True success vs handoff≠done).
10. **Handoff ≠ done** — session end and soft compact only produce continuable state.
11. **Adversarius pass on the brief itself** — does any checklist become an exit ticket? Does any step assume continuous memory past a compact?
12. **Paste-block size cap** — author the paste block lean. A fresh session re-arms by being pointed at the task-file path. The brief on disk is the law and the prompt is only a POINTER to it — lean on "read the brief fully first" and keep phase detail, enumerations, and doctrine in the brief, never inlined in the prompt. This is the compactification law applied to the prompt itself: anything load-bearing lives on disk.

House templates (when present): `templates/goal-brief.md`, `templates/goal-prompt-block.md` under this skill directory.

## §9 · Operating a live goal (procedure)

1. Orient: **orientation packet** (brief → status tip → graph tip → cited exhibits → pressure).
2. Draw sortes (correct catalog); inject; plan arms.
3. Execute experiments; write exhibits first.
4. Log graph nodes with tags + kills + fan-outs + `not surfaced:`.
5. Update status only for elevation-relevant truth (not every soft KEEP).
6. **Pressure check** every re-arm window or when sick signals appear.
7. **Before any compact / pause / session end:** pre-boundary tip write (§7).
8. **After any compact / cold start:** post-boundary re-read; refuse summary warrant; hard re-arm if continuity failed.
9. Checkpoint git; if sick → end session and re-post brief.
10. Never complete task on process volume or summary residue.

## §10 · Meta acceptance tests (class-parameterized)

**All classes:**

- [ ] True success is one sentence and falsifiable
- [ ] Continuable handoff explicitly ≠ completion
- [ ] Refuse list includes count-collapse, packaging elevation, **summary-as-warrant**
- [ ] No “minimum N waves” as success
- [ ] Class named (A/B/C/D)
- [ ] Resume points at **tips**, not mid-file heads or conversation memory

**Class A (add):** prior failure modes · obstacle/fan-out protocol · full pressure package · sortes multi-arm doctrine · graph + ledger + exhibits named · **full compactification package** (orientation packet, pre/post boundary protocols)

**Class B:** bounded question list + scope/time exit allowed · survey surfaces named · light orientation packet + tip write

**Class C:** deliverable + test/smoke bar · review-sortes if multi-arm code · branch/PR tip OK

**Class D:** light surfaces · optional sortes · still refuse summary-as-warrant if multi-turn

A **class A** running loop is healthy only if: recent load-bearing falsification or named plateau+engine-change · multi-arm waves tagged · tip sources agree · standing blocks enforced · **last boundary left tips coherent** (no tip-erasure / ghost continuity).
