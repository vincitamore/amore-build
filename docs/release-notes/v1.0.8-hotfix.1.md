Coordination-plane recut. Same-seat N sessions stay on loopback. Cross-seat
live wake is Tailnet TLS only. This GitHub Release is a **full release**, not
a pre-release: `/releases/latest` must resolve here or every seat sees "no
update." The hyphen in `v1.0.8-hotfix.1` is the fork's hotfix scheme
(`1.0.8 < 1.0.8-hotfix.1 < 1.0.9`), not a GitHub pre-release flag. Do not
tick pre-release on the GitHub UI and do not pass `prerelease: true` to the
release action.

## What changed

- **Seat identity** is the Tailscale MagicDNS first label (`HOUSE_SEAT`
  first, then the shared seat file, then MagicDNS, then hostname). The
  hostname fallback is never written into the seat file. Not `unknown`
  when `HOSTNAME` is unset.
- **Wake transport** — same-seat: unix domain (POSIX) or token-gated TCP
  `127.0.0.1` (Windows). Cross-seat: TLS to the peer's Tailscale IPv4
  (house-issued cert, TOFU pin, bind that address only — never 0.0.0.0,
  never LAN). A busy session enqueues. ssh inbox is the offline fallback;
  a failed live wake is `degraded (inbox) after live wake: …`, not a
  success-shaped `sent (inbox)`.
- **Pulse** — count plus a `seat/harness` sub-line, polled with the
  Dashboard. Duplicate harness rows for the same pid collapse.
- **Unix updater (this cut onward)** — `iris-dash-*` is marked executable
  before fleet stage-smoke, so a 644 docs member no longer aborts the
  transaction.

## Hop from v1.0.8 on Unix (hide-dash, then un-hide)

The hop **from** v1.0.8 still runs the **v1.0.8 updater**. That updater
unpacks `iris-dash-*` as a 644 docs member and stage-smokes it, then
aborts:

```
smoke …/.staging/iris/docs/iris-dash-linux-x64: failed to spawn smoke command
```

Windows does not need `+x`, so the five-cell matrix was green while Unix
could not hop unaided.

1. **Hide the dash** in the install directory (parent of the running
   `amore` / `iris` binaries) so the v1.0.8 scanner does not adopt it.
   Rename the sibling away from `iris-dash-*` / `iris-dash`:

   ```sh
   cd "$(dirname "$(command -v amore)")"
   mv iris-dash-linux-x64 .iris-dash-hidden
   # darwin-arm64: iris-dash-darwin-arm64
   ```

2. **Update:** `amore update`

3. **Un-hide** the sibling (restore the original `iris-dash-*` name).
   A hidden dash is **never re-adopted**: fleet only ships dash when a
   matching sibling is already in the install dir, and `iris dash`
   re-execs only a sibling it can see (otherwise exit 64). Leaving it
   hidden drops the dash on this seat forever.

Later hops use this cut's updater and do not need hide-dash.

## After update: restart running v1.0.8 sessions

Already-running v1.0.8 processes still carry the old leader comparator
(raw semver: `1.0.8-hotfix.1` < `1.0.8`). They can force-kill the new
leader until they exit. Restart every live session on the seat after the
hop, or expect a bounded thrash window. The updater itself already orders
`1.0.8 < 1.0.8-hotfix.1 < 1.0.9`.
