The Kimi-K3 cooperation harness, with native grok subagent freight.

Selene Build is a permanent engineered fork of xAI's open-source
[`grok-build`](https://github.com/xai-org/grok-build) (Apache-2.0).
**Not an xAI product. Not a Moonshot product.** Provenance, upstream sync
cadence, and the honest delta versus stock upstream: [`UPSTREAM.md`](https://github.com/vincitamore/selene-build/blob/main/UPSTREAM.md).

This is the first public tag.

## Highlights

- **`selene` binary, Selene Build identity throughout** — label, banners,
  doctor, help and error strings. `argv0` also tolerates `selene-build`,
  `grok`, and `agent`. `selene doctor` reports a `pathCollision` when another
  `selene` on `PATH` (crates.io ships a Lua linter of that name) would shadow
  this one.
- **Guided first-run setup** — `selene setup`, or an auto-guided TUI screen on
  first launch. Kimi K3 provider paths lead; native grok is the second rail;
  the dioptra companion is offered and can be declined. Hard guards: the
  auto-launch never fires headless, in CI, or when credentials already resolve.
  `--managed` keeps the enterprise/team configuration path, `--headless` lists
  the steps without prompting, `--dry-run` writes nothing.
- **`selene init` plants a complete agent house** — `AGENTS.md`, a
  `context/ tasks/ inbox/ knowledge/ reminders/ forge/` scaffold, seven
  orchestration skills (forge-master, auriga, oeconomia, prokope, sortes, isda,
  sentinel), and a hooks pack (Stop gate + SessionStart context injection).
  The principle lattice installs by default; `--no-lattice` opts out. Everything
  is embedded in the binary — `init` needs no network. `--refresh` updates
  what the tool owns and leaves your edits alone.
- **`.selene` config semantics with `.grok` legacy fallback** — home defaults to
  `~/.selene` (`$SELENE_HOME`), project config to `.selene/` (`.grok/` still
  read; `.selene` wins when both exist). `SELENE_*` environment variables are
  primary, `GROK_*` names keep working as aliases.
- **Dioptra companion seam** — `Ctrl+Shift+D` opens `dioptra dash` in a new
  terminal when the companion is installed, and the shortcut stays hidden when
  it is not.
- **Auto-update is hard off** — a fork must never update itself back to
  upstream. The setting is still parsed for file compatibility; every effective
  read is forced false. Telemetry and feedback default off.
- **Dioptra public package** — daemon index/graph/search, the full `regula` org
  verb surface (`task`, `inbox`, `reminder`, `knowledge`), and an optional
  standalone dash, shipped as one multi-tool artifact per platform.

## Provider paths

The default model path is Kimi K3 — OpenRouter, Moonshot direct, or a
self-hosted open-weight endpoint. Native xAI grok is the second rail for
first-party catalog access and subagent freight. Bring-your-own-key is never
walled behind OAuth: a K3 key alone is a complete configuration. See the README
quickstart, [`docs/authentication.md`](https://github.com/vincitamore/selene-build/blob/main/docs/authentication.md), and
[`examples/config.multi-provider.toml`](https://github.com/vincitamore/selene-build/blob/main/examples/config.multi-provider.toml).

## Verification at this tag

- CI: Linux and Windows lanes build the release binary and run the pager,
  config, env, hooks, agent, version, and update crate suites.
- Release lanes build and smoke every published asset — each binary reports
  `--version` and answers `doctor --json` before it is packaged.
- The dioptra workspace suite runs in its own lane, and the compiled multi-tool
  is smoked on each platform it ships for.
- Every published asset has an adjacent `.sha256`.
